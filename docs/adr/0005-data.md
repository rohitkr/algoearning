# 0005 Data: PostgreSQL + Redis, two-layer user isolation

**Decision.** PostgreSQL (SQLAlchemy 2 async via psycopg 3, Alembic migrations) is the source of truth.
Redis for pub/sub (ticks, engine events), engine commands, rate limits, locks and caches.

**User isolation is enforced twice** (packages/py-db):

1. **Repositories** (`UserScopedRepo`) bind the caller's user id and add `WHERE user_id = :me` to every
   statement; `user_id`, `id` and timestamps can never be set by callers.
2. **Row-level security** in PostgreSQL (`ae_db/rls.py`): every user-owned table has `FORCE ROW LEVEL
SECURITY` and a policy `user_id = app_user_id()`. Requests run as the `ae_app` role with the user id set
   transaction-locally (`SET LOCAL`), so even a query that forgets its filter, or tries to write another
   user's `user_id`, is filtered/rejected by the database. Trusted paths (sign-in sync, webhooks, engine,
   admin) use `ae_system`. `webhook_events` is system-only; `plans` is read-only for users.

Tests prove both layers independently, and a mutation check confirmed the RLS tests fail if RLS is removed.

**Also:** enums are VARCHAR + CHECK (cheap to extend); money/prices are NUMERIC; `audit_log` is append-only
(a trigger rejects UPDATE/DELETE, for the owner too); list endpoints use keyset (cursor) pagination.
